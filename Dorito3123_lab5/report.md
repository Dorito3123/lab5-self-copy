# Отчет по лабораторной работе №14

## Тема работы

**AVL, Red-Black и B-tree: поисковый индекс**

## Цель работы

Целью данной лабораторной работы является реализация трех структур данных:

- AVL-дерева;
- Red-Black Tree;
- B-tree.

После реализации эти структуры используются для построения инвертированного текстового индекса. На основе индекса выполняется поиск по корпусу вопросов Stack Overflow. Также проводится сравнение трех структур по скорости индексации, скорости поиска и потреблению памяти.

Главная идея лабораторной работы заключается в том, чтобы не просто реализовать деревья поиска отдельно, а применить их в практической задаче — создании небольшого поискового движка.

---

## Постановка задачи

В лабораторной работе необходимо реализовать поисковую систему, которая работает с набором вопросов Stack Overflow.

Для каждого вопроса известны:

- идентификатор документа;
- заголовок вопроса;
- набор слов, полученный после обработки текста.

На основе этих данных строится инвертированный индекс. Затем пользователь может выполнить поисковый запрос, а программа должна найти документы, содержащие слова из этого запроса.

Для хранения индекса используются три разные структуры данных:

1. AVL-дерево;
2. Red-Black Tree;
3. B-tree.

После этого необходимо сравнить, какая структура работает быстрее при построении индекса и при поиске.

## Инвертированный индекс

Инвертированный индекс — это структура данных, которая используется в полнотекстовом поиске.

Обычное представление документов выглядит так:

```text
документ → список слов
```

Например:

```text
Документ 1 → python, list, sort
Документ 2 → c, pointer, memory
Документ 3 → python, memory, error
```

Инвертированный индекс хранит данные наоборот:

```text
слово → список документов
```

Например:

```text
python  → [Документ 1, Документ 3]
list    → [Документ 1]
sort    → [Документ 1]
memory  → [Документ 2, Документ 3]
```

Такой подход удобен для поиска. Если пользователь вводит запрос:

```text
python list
```

то программа сначала находит список документов для слова `python`, потом список документов для слова `list`, а затем пересекает эти списки. В результате остаются только те документы, где встречаются оба слова.

## Posting list

Для каждого слова в индексе хранится список документов, где это слово встречается. Такой список называется `posting list`.

В проекте один элемент posting list описывается структурой:

```c
typedef struct {
    int  doc_id;
    char title[256];
} PostingEntry;
```

Поля структуры:

- `doc_id` — идентификатор документа;
- `title` — заголовок вопроса.

Например, для слова `python` posting list может выглядеть так:

```text
python → [
    (1, "How to sort a list in Python"),
    (3, "Python memory error")
]
```

Для хранения posting list используется универсальный `Vector` из предыдущей лабораторной работы.

Основные функции для работы с posting list:

```c
Vector* createPostingList(void);
void appendPosting(Vector* list, int doc_id, const char* title);
Vector* clonePostingList(const Vector* list);
```

Функция `createPostingList` создает пустой список.

Функция `appendPosting` добавляет в список новый документ.

Функция `clonePostingList` создает копию списка.

## AVL-дерево

AVL-дерево — это самобалансирующееся бинарное дерево поиска.

Главное условие AVL-дерева: для каждого узла разница высот левого и правого поддерева не должна превышать 1.

Если после вставки элемента это условие нарушается, дерево выполняет балансировку с помощью поворотов.

В проекте узел AVL-дерева имеет следующий вид:

```c
typedef struct AVLNode {
    char*           key;
    int             height;
    Vector*         postings;
    struct AVLNode* left;
    struct AVLNode* right;
} AVLNode;
```

Где:

- `key` — слово;
- `height` — высота узла;
- `postings` — список документов для данного слова;
- `left` — левый потомок;
- `right` — правый потомок.

Само дерево описывается структурой:

```c
typedef struct {
    AVLNode* root;
    int      size;
} AVLTree;
```

Основные функции:

```c
AVLTree* createAVLTree(void);
void freeAVLTree(AVLTree* tree);
void avlInsert(AVLTree* tree, const char* key, int doc_id, const char* title);
Vector* avlSearch(const AVLTree* tree, const char* key);
```

Если при вставке слово уже есть в дереве, новый документ добавляется в уже существующий posting list. Если слова еще нет, создается новый узел дерева.

### Особенности AVL-дерева

Преимущества:

- быстрый поиск;
- дерево хорошо сбалансировано;
- высота дерева остается небольшой.

Недостатки:

- при вставке часто нужно выполнять повороты;
- поддержание строгого баланса требует дополнительных операций.

AVL-дерево хорошо подходит для задач, где поиск выполняется часто, а количество вставок относительно меньше.

## Red-Black Tree

Red-Black Tree — это самобалансирующееся бинарное дерево поиска. В отличие от AVL-дерева, оно поддерживает баланс менее строго.

Каждый узел в Red-Black Tree имеет цвет:

- красный;
- черный.

Узел Red-Black Tree в проекте:

```c
typedef enum { RB_RED, RB_BLACK } RBColor;

typedef struct RBNode {
    char*          key;
    RBColor        color;
    Vector*        postings;
    struct RBNode* left;
    struct RBNode* right;
    struct RBNode* parent;
} RBNode;
```

Где:

- `key` — слово;
- `color` — цвет узла;
- `postings` — список документов;
- `left` — левый потомок;
- `right` — правый потомок;
- `parent` — родительский узел.

Само дерево:

```c
typedef struct {
    RBNode* root;
    RBNode* nil;
    int     size;
} RBTree;
```

В Red-Black Tree используется специальный sentinel-узел `nil`, который обозначает черные листья.

Основные функции:

```c
RBTree* createRBTree(void);
void freeRBTree(RBTree* tree);
void rbInsert(RBTree* tree, const char* key, int doc_id, const char* title);
Vector* rbSearch(const RBTree* tree, const char* key);
```

### Особенности Red-Black Tree

Преимущества:

- хорошая скорость вставки;
- меньше строгих ограничений, чем в AVL;
- используется в реальных системах, например в Java TreeMap и ядре Linux.

Недостатки:

- реализация сложнее обычного бинарного дерева;
- поиск может быть немного медленнее, чем в AVL, так как дерево менее строго сбалансировано.

Red-Black Tree хорошо подходит для задач, где часто выполняются вставки и изменения структуры.

---

## B-tree

B-tree — это дерево поиска, в котором один узел может хранить сразу несколько ключей.

В данной лабораторной работе используется B-tree с минимальной степенью:

```c
#define BTREE_T 3
```

Это значит, что один узел может хранить от `t - 1` до `2t - 1` ключей.

При `t = 3` один узел может хранить максимум 5 ключей.

Структура узла B-tree:

```c
typedef struct BTreeNode {
    char*             keys[BTREE_MAX_KEYS];
    Vector*           postings[BTREE_MAX_KEYS];
    struct BTreeNode* children[BTREE_MAX_CH];
    int               n;
    int               is_leaf;
} BTreeNode;
```

Где:

- `keys` — массив ключей;
- `postings` — массив posting list'ов;
- `children` — массив дочерних узлов;
- `n` — текущее количество ключей в узле;
- `is_leaf` — признак листового узла.

Само дерево:

```c
typedef struct {
    BTreeNode* root;
    int        size;
} BTree;
```

Основные функции:

```c
BTree* createBTree(void);
void freeBTree(BTree* tree);
void btreeInsert(BTree* tree, const char* key, int doc_id, const char* title);
Vector* btreeSearch(const BTree* tree, const char* key);
```

### Особенности B-tree

Преимущества:

- хорошо работает с большими объемами данных;
- имеет меньшую высоту за счет хранения нескольких ключей в одном узле;
- лучше использует кэш процессора;
- применяется в базах данных и файловых системах.

Недостатки:

- сложнее реализовать;
- при вставке нужно обрабатывать переполнение узлов;
- внутри одного узла приходится искать нужный ключ среди нескольких.

B-tree особенно полезно, когда данных много и обычные бинарные деревья становятся менее эффективными из-за большого количества переходов по указателям.

## Общий интерфейс Index

Чтобы поисковая система могла работать с разными деревьями одинаковым образом, был реализован общий интерфейс `Index`.

Тип дерева задается перечислением:

```c
typedef enum {
    TREE_AVL,
    TREE_RB,
    TREE_BTREE
} TreeType;
```

Сам индекс описывается структурой:

```c
typedef struct {
    void*    tree;
    TreeType type;
} Index;
```

Поле `tree` хранит указатель на конкретное дерево.

Поле `type` показывает, какое дерево используется.

Основные функции:

```c
Index* createIndex(TreeType type);

void indexDocument(Index* idx, int doc_id, const char* title,
                   const char** tokens, int n_tokens);

Vector* lookupTerm(const Index* idx, const char* term);

void saveIndex(const Index* idx, const char* path);

Index* loadIndex(const char* path, TreeType type);

void freeIndex(Index* idx);
```

### Функция createIndex

Функция `createIndex` создает индекс нужного типа.

Если выбран тип `TREE_AVL`, внутри создается AVL-дерево.

Если выбран тип `TREE_RB`, внутри создается Red-Black Tree.

Если выбран тип `TREE_BTREE`, внутри создается B-tree.

### Функция indexDocument

Функция `indexDocument` добавляет документ в индекс.

Она получает:

- указатель на индекс;
- `doc_id`;
- заголовок документа;
- массив токенов;
- количество токенов.

Для каждого токена вызывается вставка в соответствующее дерево.

Пример логики:

```text
если индекс AVL → вызвать avlInsert
если индекс Red-Black → вызвать rbInsert
если индекс B-tree → вызвать btreeInsert
```

### Функция lookupTerm

Функция `lookupTerm` ищет слово в индексе.

В зависимости от типа дерева вызывается соответствующая функция поиска:

```text
AVL       → avlSearch
Red-Black → rbSearch
B-tree    → btreeSearch
```

Результатом является posting list для найденного слова.

### Функции saveIndex и loadIndex

Функция `saveIndex` сохраняет индекс в файл.

Функция `loadIndex` загружает индекс из файла.

Это нужно для того, чтобы не строить индекс заново при каждом запуске поиска.

## Поиск

Поиск запускается командой:

```bash
./app search --type=avl "python list sort"
```

Также можно искать через Red-Black Tree:

```bash
./app search --type=rb "memory leak"
```

Или через B-tree:

```bash
./app search --type=btree "balanced tree"
```

Алгоритм поиска:

1. пользователь вводит строку запроса;
2. запрос разбивается на отдельные слова;
3. для каждого слова выполняется поиск в дереве;
4. для каждого слова получается posting list;
5. posting list'ы пересекаются;
6. выводятся документы, содержащие все слова запроса.

Если запрос состоит из одного слова, программа просто возвращает posting list этого слова.

Если запрос состоит из нескольких слов, то используется AND-семантика. Это значит, что документ должен содержать все слова из запроса.

Пример:

```text
Запрос: python list
```

Документ попадет в результат только если в нем есть и `python`, и `list`.

## SearchResult

Результат поиска описывается структурой:

```c
typedef struct {
    int  doc_id;
    char title[256];
    int  score;
} SearchResult;
```

Поля:

- `doc_id` — идентификатор найденного документа;
- `title` — заголовок документа;
- `score` — оценка релевантности.

Общий результат поиска хранится в структуре:

```c
typedef struct {
    Vector* results;
    int     total;
    double  time_ms;
} SearchResults;
```

Где:

- `results` — список найденных документов;
- `total` — общее количество найденных документов;
- `time_ms` — время выполнения поиска в миллисекундах.

## Пересечение posting list'ов

Для поиска по нескольким словам необходимо пересекать списки документов.

Например:

```text
python → [1, 2, 5, 8]
list   → [1, 5, 7]
```

После пересечения:

```text
python AND list → [1, 5]
```

В результате остаются только документы, которые содержат оба слова.

Именно эта операция часто занимает больше времени, чем сам поиск слова в дереве, особенно если posting list'ы большие.

## Fuzzy Search

Дополнительно был реализован нечёткий поиск.

Нечёткий поиск нужен для ситуаций, когда пользователь допустил ошибку в слове.

Например:

```text
pythn
```

может быть сопоставлено со словом:

```text
python
```

Для этого используется расстояние Левенштейна.

Расстояние Левенштейна показывает, сколько операций нужно сделать, чтобы превратить одну строку в другую.

Разрешенные операции:

- вставка символа;
- удаление символа;
- замена символа.

Например:

```text
pythn → python
```

Здесь нужно добавить букву `o`, поэтому расстояние равно 1.

### Алгоритм fuzzy search

Алгоритм работает следующим образом:

1. для каждого слова запроса выполняется обход всего дерева;
2. для каждого ключа считается расстояние Левенштейна;
3. если расстояние не больше заданного `max_distance`, слово считается кандидатом;
4. для каждого кандидата берется posting list;
5. документы объединяются;
6. результаты ранжируются.

Структура кандидата:

```c
typedef struct {
    char    term[256];
    int     distance;
    Vector* postings;
} FuzzyCandidate;
```

Основные функции:

```c
Vector* fuzzyFindCandidates(Index* idx, const char* term, int max_distance);
SearchResults* fuzzySearch(Index* idx, const char* query, int max_distance);
```

Формула ранжирования:

```text
score = matched_terms * 10 - avg_distance
```

Чем больше совпавших слов и чем меньше среднее расстояние, тем выше результат.

Примеры запуска:

```bash
./app search --type=avl --fuzzy --max-dist=2 "pythn lst"
./app search --type=rb --fuzzy --max-dist=1 "sortig"
```

### Особенность fuzzy search

Нечёткий поиск работает заметно медленнее обычного поиска, потому что ему нужно обходить все слова в дереве и для каждого считать расстояние Левенштейна.

Обычный поиск работает примерно за `O(log n)`, а fuzzy search требует полного обхода всех уникальных слов.

## Время индексации

Измерялось время построения индекса для разного количества документов.

| Документов | AVL (с) | Red-Black (с) | B-tree (с) |
|---:|---:|---:|---:|
| 10 000 | 0.272 | 0.304 | 0.279 |
| 30 000 | 0.893 | 0.999 | 0.909 |
| 50 000 | 1.535 | 1.697 | 1.606 |

По результатам видно, что на данном наборе данных AVL-дерево показало немного лучшее время индексации, чем Red-Black Tree. B-tree оказалось примерно посередине.

Обычно можно ожидать, что Red-Black Tree будет хорошо показывать себя при частых вставках, но в конкретной реализации на результат влияют детали кода, работа со строками, posting list'ами и выделением памяти.

Также видно, что с увеличением количества документов время индексации растет ожидаемо: чем больше документов и токенов нужно обработать, тем больше вставок выполняется в дерево.

## Время поиска

Измерялось среднее время поиска для запросов разной длины.

| Количество слов | AVL (мс) | Red-Black (мс) | B-tree (мс) |
|---:|---:|---:|---:|
| 1 | 0.0594 | 0.0602 | 0.0596 |
| 2 | 1.4325 | 1.4057 | 1.4167 |
| 3 | 1.2626 | 1.2726 | 1.2665 |

Однословный поиск работает очень быстро, потому что для него требуется только найти один ключ в дереве и вернуть соответствующий posting list.

Для запросов из двух и трех слов время поиска больше. Это связано с тем, что после поиска слов нужно пересекать posting list'ы.

На практике основная часть времени при многословных запросах уходит не на поиск ключей в дереве, а на обработку списков документов.

Поэтому различия между AVL, Red-Black Tree и B-tree при поиске оказались небольшими.

## Результаты fuzzy search

Для проверки нечёткого поиска были выполнены запросы с ошибками.

Примеры:

```bash
./app search --type=avl --fuzzy --max-dist=2 "pythn lst"

```

Примерные результаты:

| Режим | Запрос | Время | Найдено |
|---|---|---:|---:|
| exact | "python list" | 1.5 мс | 202 |
| fuzzy dist=1 | "pythn list" | ~750 мс | ~11000 |
| fuzzy dist=2 | "pythn lst" | ~1470 мс | ~46000 |

Из результатов видно, что fuzzy search значительно медленнее обычного поиска.

Это связано с тем, что обычный поиск сразу идет по дереву к нужному ключу, а fuzzy search должен обойти все ключи и сравнить каждый с запросом.

Также при увеличении допустимого расстояния Левенштейна возрастает количество найденных кандидатов, поэтому растет и количество документов в результате.

## Сравнение трех структур

### AVL-дерево

AVL-дерево строго поддерживает баланс.

Из-за этого оно хорошо подходит для быстрого поиска. Высота дерева остается небольшой, поэтому поиск выполняется эффективно.

Но строгая балансировка может увеличивать затраты при вставке, так как после добавления нового узла иногда требуется выполнять повороты.

### Red-Black Tree

Red-Black Tree поддерживает баланс менее строго.

Оно часто используется в ситуациях, где важна хорошая скорость вставки и удаления. За счет менее строгих правил дерево может выполнять меньше балансировочных действий.

В данной работе Red-Black Tree показало результаты, близкие к AVL и B-tree.

### B-tree

B-tree отличается от AVL и Red-Black Tree тем, что один узел хранит несколько ключей.

Это уменьшает высоту дерева и делает структуру более кэш-дружелюбной.

B-tree часто используется в базах данных и файловых системах, где важно эффективно работать с большими объемами данных.

В данной лабораторной работе B-tree показало близкие результаты к другим деревьям.
